# Social Club football engine

Start with [current status, completed fixes and pending work](STATUS.md) before planning changes or reporting the backlog.

This is the canonical 5v5 engine. Change football decisions and execution in `src/`, not in the audition's compatibility modules. The browser training board and its ordinary matches import this build; a background job can execute the same JSON request without a browser. No external service or runtime dependency is required.

From the repository root:

```sh
npm run build:football-engine
npm run verifica:football-engine
```

```js
import {createSimulationRequest, runSimulation, runTraining} from './packages/football-engine/dist/index.js';

const request = createSimulationRequest({
  kind: 'match', fixture, durationSeconds: 900,
  coaching: {
    kind: 'repeat-one-two', side: 0, carrier: 3, partner: 5,
    channelY: 0, width: 20, emphasis: 0.6,
  },
});
const match = runSimulation(request);
const drill = runTraining({fixture, setup, durationSeconds: 20});
```

A request snapshots the full fixture (including seed, skills, traits, lineup and tactics), coaching/playbook configuration and execution settings. Results retain that input and the source build fingerprint. Save the request and result in the eventual game's storage. A different build is rejected rather than silently switching simulation versions. Seeded reproduction is verified within the same runtime; it is not a guarantee across JavaScript engines. Browser and Node math differed by roughly 3e-17 in an observed early velocity, eventually producing different outcomes in a 15-minute run. Official matches must be computed once by the authoritative job runtime, then watched from stored frames/events—not recomputed by clients from the seed. The Node adapter and browser worker attach their runtime information. JavaScript permits [implementation-approximated math](https://tc39.es/ecma262/2025/multipage/numbers-and-dates.html#sec-math.hypot). `scripts/simulate.mjs request.json result.json` is the local/background-process adapter; scheduling, authentication and persistence remain application responsibilities. Nothing has been deployed or scheduled by this extraction.

Preserve the design: instructions shape choices and supporting movement; emphasis never modifies execution accuracy. Zero emphasis restores ordinary play. Players retain situational judgment. Practice and matches share decisions, physics and truthful event traces. Recognize relationships and useful continuations rather than exact starting coordinates. Named assignments will need explicit reassignment when squad members change. Authored plans now carry `emphasis` (0–1), affecting option preferences, supporting movement and selection among eligible plans. Plans with distinct participants can run together. Overlapping plans wait while the earlier passage remains active; actual receiver changes can end a conflicting passage. Prepared actions include their plan identity. A pass job with a named `recipient` can set `repeat: true` to use the shared give-and-go behavior until a shot, interruption or a new responsibility. The board saves tactics locally and can activate several in an ordinary match; server-side club persistence remains future work. Receivers can anticipate the next coached moment during flight, while activation and receipt traces still require real contact.

A stationary prepared player must reach a physically usable striking stance, not merely enter the movement target’s arrival radius. When both player and ball have stopped close to that target but release remains unavailable, the controller completes a precise step without dragging the settled ball through repeated settling touches. Normal moving approaches retain their arrival tolerance; new ball motion or a usable stance ends the correction. Acceleration, body collisions and actual foot contact still govern execution. The corrective step ends on physical readiness, with no extra positional dead zone that could leave a side-foot exit blocked.

Short-horizon release-risk evaluation projects both the passer and opponents from visible momentum over the same preparation interval (capped at 0.3 s). It does not hold the passer at the old position while advancing opponents. Immediate release uses current geometry; the forecast neither reads private opponent plans nor changes kick physics/accuracy.

Opponent information is separate from teammate coordination. Defensive cover and marking during flight use an independently predicted receiver from the visible ball trajectory and reachable players, not the private intended/committed receiver. Authored activation and prepared runner cues do not reset the opposing decision clock. Physical events and visible movement still support anticipation. This boundary is covered by counterfactual tests; it is not a full individual sight, attention or uncertainty model.

Carrier choice is independent of how many execution variants a generator samples. After the existing viability/continuity filter, `practice-selection.ts` groups ground/through/loft deliveries by recipient, carry routes together, clearances together, and take-ons by opponent; shooting remains separate. Each group's best scored opportunity supplies its weight, shared by its execution variants. A new equally rated direction cannot make that intention more likely; a genuinely better route or another recipient can change the comparison. Exact duplicate candidates add no weight. Personality and manager adjustments remain in the scores, and one random draw selects the actual option without changing its execution data. These groups have no fixed priority. Adding a new action technique requires explicitly deciding its intention group, not accidentally granting another chance to pursue the same idea.

Off-ball instruction producers propose responsibilities through a read-only coordination view. The coordinator reserves accepted responsibilities before allocating ordinary jobs; pressure arrangements keep those responsibilities and adjust the remaining players around them. Receiving/collecting a live ball and unavailable physical states take priority. Defensive exposure is a finite shared cost, not a requirement for a teammate behind every runner. Persistent `standing` instructions use that same boundary: press, mark a numbered opponent, protect a lesson space, or stay forward in a lesson space. Each has `id`, numeric `actor`, `kind`, and `phase` (`defending` or `always`); marking adds `opponent`, positioning adds `spaceId`. Press/mark use the defending phase. At most four distinct actors per plan are accepted. The coordinated policy accounts for an instructed presser and existing marks before assigning remaining defenders; there is no mandatory press/cover quota. The historical classic policy rejects these instructions explicitly.

Persistent policies are considered again across possession changes. Their emphasis is sampled once per possession phase (100% pursues each applicable phase); it does not reroll every quarter-second or change skill. Conflicts use plan emphasis/weight, with active combinations retaining their participants. `standingNotes` report active, waiting and inactive intentions, not guaranteed execution. The board authors and saves these policies, requires explicit reassignment for missing named players, and shows them during practice and match replay. `playbookSelections` also reports participant conflicts and ending details for combinations. Each entry in `PracticeResult.playbookSelections` carries `side` (0 or 1), the team whose playbook made that selection, including unnamed `Joc liber` fallbacks; it is reporting only and does not change play (optional in the `PlaybookSelection` type because live playbook objects omit it).

`deliverables/football-practice/engine-audition/local-five-sandbox/runtime` contains generated re-exports for existing checks and experiments. The older 11v11 football lab and historical comparison engines remain separate. The local server serves only compiled package modules, never arbitrary workspace files. After editing source, rebuild before running the local server or a background job.

Team approaches are ordinary fixture tactics: `teamApproaches` exports Balanced, Short combinations, Direct and Counter presets; `validateApproach` normalizes their editable settings. `transition` reads forward space and recovering opponents after a real possession change, expires, and resets on restarts. Keeper catches and deep recoveries can launch complementary runs while retaining an outlet and cover; an organised opponent closes the counter invitation. Progression preferences affect both carrier options and support allocation; skills and physical delivery plans remain unchanged. The match preparation UI saves named approaches locally and can compare one against Balanced with custom combinations disabled in both runs, retaining both input snapshots.

Take-ons retain their initial fake/burst, then periodically reconsider substantially better releases using ordinary football and manager scores. The original commitment and stronger current duel remain meaningful; repeat-attempt penalties do not apply to reconsidering the same attempt. Releasing still requires normal preparation and physical foot contact. See [current status and evidence](STATUS.md).

Prepared ordinary foot shots also recheck at physical release using the existing 0.18 reconsideration margin: a disappeared opportunity or clearly better alternative returns to ordinary selection and preparation. This does not change finishing accuracy or force a pass. First-time, aerial and set-piece evaluations retain their separate paths.

Triggered substitutions (opt-in, `substitutionOrders` on a match input; [src](src/practice-substitutions.ts)): each order is `{id, side, in, out?, trigger, notBefore?}` with squad ids. `trigger` is `{kind:'tired', player, threshold}` (live energy 0–100 below `threshold`; `out` is that player), `{kind:'score', state:'losing'|'drawing'|'winning'}`, `{kind:'margin', atLeast, direction:'up'|'down'}` or `{kind:'half'}` (from `duration/2`, i.e. 7:30 of 15 minutes; 45:00 of 90). At most three orders per side. `in` must start on the bench and appears in one order only. `out` may be a starter or someone another order brings on. Without `out`, the most tired on-pitch player of the same kind (keeper/outfield) goes off. Keepers (`roles[0]==='GK'`) only replace the keeper slot, and vice versa. Triggers are checked only at stoppages (goal, out of play, foul, offside, half-time). The change is made at the first restart where the trigger holds, never at the opening kickoff, before restart positions and the taker are chosen. Score and margin change only at goals, and goals always stop play, so this is exactly "the next restart after the trigger becomes true". The newcomer enters at the departing player's spot during the dead ball. He takes that player's role, lane and lineup slot number. Slot-addressed plans (#2–#5), lessons and standing instructions therefore pass to him; he gets his own skills, traits, energy and pace. A player who went off never returns. Each change records a `substitution` event (`side`, `outgoing`, `incoming`, `substitution:{order, trigger, energy, score}`); `substitutionNotes` reports each order as made, waiting or impossible. Orders cannot be combined with `substitutions:'planned'`, a coaching intention, or training. Omitted or empty orders run none of this code and leave the input snapshot unchanged ([parity](evidence/2026-09-25-triggered-subs/README.md)).

Replay evidence: `goal.side` identifies the benefiting team; `actor` and `lastTouch` identify the final touch, not an adjudicated scorer. Shot events include actual launch origin/velocity and intended aim. The optional ordinary foot-shot `assessment` is a decision heuristic, not expected goals; aerial strikes and free kicks omit it.
